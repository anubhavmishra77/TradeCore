# Database Design

## Tables
`users`, `instruments`, `wallets`, `orders`, `executions`, `positions`.

## Key decisions
- UUID primary keys, generated by the database.
- Money stored as `NUMERIC(20,4)` — never floating point.
- `orders` has a unique constraint on `(user_id, idempotency_key)`; this is the
  enforcement point for retry safety (see ADR-003).
- `executions` is append-only; positions are derived and reconciled nightly.
- `wallets.available_balance` and `blocked_balance` are both non-negative by CHECK constraint.

## Indexes
- `orders (user_id, status)` for the open-orders screen
- `executions (order_id)` for fill history
- `instruments (symbol)` for search

## Migrations
Flyway, versioned `V1..Vn`, never edited after merge.
